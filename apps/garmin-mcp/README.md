# Garmin MCP

A private, read-only remote MCP server that gives Claude access to your own Garmin Connect data on web, desktop and mobile. It runs on Cloudflare Workers behind Cloudflare Access, which lets only the owner's GitHub account in.

## Tools

| Tool | Use it for |
|---|---|
| `list_activities(start_date, end_date, type?)` | Finding workouts and their ids |
| `get_activity(id)` | One workout's summary, laps and planned structured workout |
| `get_activity_streams(id, resolution?)` | Time series for detailed analysis, 10s per point by default |
| `get_heart_rate_zones()` | Heart-rate zones per sport, and the max/resting/threshold HR behind them |
| `get_daily_health(start_date, end_date?)` | Sleep, HRV, resting HR, stress and Body Battery, up to 92 days |

Responses use SI units plus pace in min/km, and are capped at 100,000 characters with a note when anything is reduced. GPS coordinates are never read from FIT files or returned.

## How it works

```
claude.ai ──OAuth──▶ Cloudflare Access (Managed OAuth, GitHub login, owner-only policy)
    │
    └──MCP──▶ Cloudflare Worker ──▶ Garmin Personal API
                │  checks that Access authenticated the request
                │  createMcpHandler: stateless Streamable HTTP at /mcp
                │  served at https://garmin-mcp.tsutsu.dev
                └─ KV: GARMIN_CACHE (token, activities, parsed FIT)
```

Decisions worth knowing about:

- **`createMcpHandler`, not `McpAgent`.** Cloudflare has deprecated `McpAgent`. These tools are stateless, so no Durable Object is needed.
- **Cloudflare Access is the OAuth server.** The Access application for `*.tsutsu.dev` has Managed OAuth on, so claude.ai signs in through Access and GitHub. The Worker has no auth code of its own. It refuses any request that Access didn't authenticate (`ctx.access`), and it never sees an OAuth token.
- **The owner check lives in the Access policy.** It requires a GitHub login and the owner's email. Access can't match a numeric GitHub id, so the email is the identity, and it's re-checked whenever Access refreshes the 15-minute access token.
- **Laps come from the FIT file.** Garmin's JSON only has splits grouped by type, so `get_activity` also downloads and caches the FIT file.

### Caching

| Data | Where | Lifetime |
|---|---|---|
| Garmin access token (24h) | `GARMIN_CACHE`, keyed by a hash of the API key | Refreshed under 1h remaining, and once after a 401 |
| Activity summary | `GARMIN_CACHE` | 7 days, because names and elevation correction can change |
| Parsed FIT (no GPS) | `GARMIN_CACHE` | 90 days |
| Planned workout for an activity | `GARMIN_CACHE` | 90 days |
| Daily health | Not cached | Today's values keep changing |

### Cloudflare plan

Parsing a FIT file takes tens of milliseconds of CPU (about 20–40ms for a 40-minute run), and long activities take more. The Workers Free plan allows 10ms per request, so uncached `get_activity` and `get_activity_streams` calls can fail there with error 1102. **Use Workers Paid** ($5/month), which allows up to 30 seconds. The other tools don't parse FIT files.

## Setup

You need Node 22+, a Cloudflare account, and a Garmin Personal API key from [Garmin Connect](https://connect.garmin.com/app/settings/personalApiToken).

This app lives in the `ortix/apps` monorepo. Install from the repo root, and run the commands below from `apps/garmin-mcp/`:

```bash
npm ci
```

### Local development

Locally, wrangler simulates the Access login (the `access.dev` block in `wrangler.jsonc`), so no sign-in is needed.

1. Create `.dev.vars` (gitignored) from the example:

   ```bash
   cp .dev.vars.example .dev.vars
   ```

2. Add your Garmin key from your environment, so it never appears in output:

   ```bash
   printf 'GARMIN_API_KEY=%s\n' "$GARMIN_TOKEN" >> .dev.vars
   ```

3. Start the Worker, then run the Inspector check in a second terminal. It calls every tool and prints only sizes and errors.

   ```bash
   npm run dev
   ```

   ```bash
   scripts/inspector-check.sh
   ```

To check the Garmin client alone, `npm run smoke` prints field names and counts, never values.

### Tests

```bash
npm run typecheck
```

```bash
npm test
```

Tests run inside workerd with Garmin mocked and the Access context simulated. The FIT fixture is synthetic, generated by `scripts/make-fixture.ts`, with no GPS or real data.

## Deploy

The KV namespace, Custom Domain and `MCP_SERVER_URL` are already set in `wrangler.jsonc`, and the `GARMIN_API_KEY` secret is already on the Worker.

1. The Worker is served on the Custom Domain `garmin-mcp.tsutsu.dev`, set in `routes`. Cloudflare creates the DNS record and certificate on deploy. `workers.dev` and preview URLs are off, because they would bypass Access.
2. Deploys go through the platform's CI and keep the existing secrets, because `wrangler deploy` never deletes or changes them. This app has `"autoDeploy": false` in `package.json`, so merging a change doesn't deploy it. Deploy it from the repo's **Actions** tab: **Deploy** › **Run workflow** › app `garmin-mcp`. The run deploys, then checks `/healthz` through Access with the CI service token.
3. Watch production logs, filtered to paths, status codes and the Worker's own log lines:

   ```bash
   scripts/tail.sh
   ```

### Split DNS on the home network

`tsutsu.dev` was set up as Tailscale split DNS, pointed at the UniFi gateway (`192.168.1.1`), which answered `*.tsutsu.dev` with a LAN address. The gateway had a **Forward Domain** policy sending `garmin-mcp.tsutsu.dev` to `1.1.1.1`, so browsers at home and on the tailnet reached Cloudflare for the sign-in. If that's still in place, every public app on `*.tsutsu.dev` needs the same forwarding to be usable from a browser at home. claude.ai itself is unaffected either way.

## Add the connector on claude.ai

1. Go to [Customize > Connectors](https://claude.ai/customize/connectors) and click **Add custom connector**. On Team or Enterprise plans an owner adds it under Organization settings > Connectors.
2. Enter `https://garmin-mcp.tsutsu.dev/mcp` and click **Add**. Leave the OAuth client fields empty.
3. Click **Connect** and sign in through Cloudflare Access with the owner's GitHub account.
4. In a chat, turn it on from the **+** button under **Connectors**. Connectors you add on the web are also available in Claude on desktop and mobile.

## Rotate the Garmin key

Garmin keys last 30, 90, 180 or 365 days, and Garmin emails you about a week before expiry. When a key has expired, tools return a message telling you to rotate it.

1. Create a new key at [Garmin Connect](https://connect.garmin.com/app/settings/personalApiToken). It's shown only once.
2. Update `GARMIN_TOKEN` in your shell profile and open a new terminal.
3. Replace the Worker secret, which takes effect immediately:

   ```bash
   printenv GARMIN_TOKEN | npx wrangler secret put GARMIN_API_KEY
   ```

4. Update `GARMIN_API_KEY` in `.dev.vars` if you develop locally.
5. Delete the old key on the Garmin page.

There's nothing to clear: the token cache is keyed by a hash of the API key, so a new key misses the old entry automatically. The connector on claude.ai keeps working.

## Security

- All tools are read-only and annotated as such. There is no authless endpoint or fallback.
- Sign-in is entirely Cloudflare Access: the Worker stores no grants or OAuth tokens and holds no GitHub credentials.
- Logs go through `src/log.ts`, which only has fields for request id, tool name, outcome, status and timing. Cloudflare's invocation logs are off, because they would record full URLs, including OAuth codes. Error messages never include Garmin's response bodies.
- Access issues 15-minute access tokens and 30-day grants (the Access application's Managed OAuth settings). Expect to click **Connect** again on claude.ai about once a month.
- To cut off access, change the Access policy or revoke the user's sessions in Zero Trust. Access re-checks the policy every time it refreshes a token.
- The only secret is `GARMIN_API_KEY`, in Wrangler secrets and the gitignored `.dev.vars`. Check for staged secrets before committing.
