# Garmin MCP

A private, read-only remote MCP server that gives Claude access to your own Garmin Connect data on web, desktop and mobile. It runs on Cloudflare Workers, and only one allowlisted GitHub account can sign in.

## Tools

| Tool | Use it for |
|---|---|
| `list_activities(start_date, end_date, type?)` | Finding workouts and their ids |
| `get_activity(id)` | One workout's summary, laps and planned structured workout |
| `get_activity_streams(id, resolution?)` | Time series for detailed analysis, 10s per point by default |
| `get_heart_rate_zones()` | Heart-rate zones per sport, and the max/resting/threshold HR behind them |
| `get_daily_health(start_date, end_date?)` | Sleep, HRV, resting HR, stress and Body Battery, up to 92 days |

Responses use SI units plus pace in min/km, and are capped at 100,000 characters with a note when anything is reduced. GPS coordinates are never read from FIT files or returned.

## How it works

```
claude.ai ──OAuth + MCP──▶ Cloudflare Worker ──▶ Garmin Personal API
                             │  OAuthProvider: tokens, discovery, client registration
                             │  /authorize, /callback: consent, then GitHub login and allowlist
                             │  createMcpHandler: stateless Streamable HTTP at /mcp
                             │  served at https://garmin-mcp.tsutsu.dev
                             └─ KV: OAUTH_KV (grants), GARMIN_CACHE (token, activities, parsed FIT)
```

Decisions worth knowing about:

- **`createMcpHandler`, not `McpAgent`.** Cloudflare has deprecated `McpAgent`. These tools are stateless, so no Durable Object is needed.
- **One Worker with the combined `OAuthProvider`.** Cloudflare fully supports this for a Worker that is its own only resource. It keeps a single URL, deploy and set of secrets.
- **No `COOKIE_ENCRYPTION_KEY`.** The OAuth library binds consent and sign-in to the browser with its own `__Host-` cookies and encrypted server-side state.
- **Allowlist by numeric GitHub id.** Usernames can change hands. The id is checked at login and again on every request.
- **Laps come from the FIT file.** Garmin's JSON only has splits grouped by type, so `get_activity` also downloads and caches the FIT file.

### Caching

| Data | Where | Lifetime |
|---|---|---|
| Garmin access token (24h) | `GARMIN_CACHE`, keyed by a hash of the API key | Refreshed under 1h remaining, and once after a 401 |
| Activity summary | `GARMIN_CACHE` | 7 days, because names and elevation correction can change |
| Parsed FIT (no GPS) | `GARMIN_CACHE` | 90 days |
| Planned workout for an activity | `GARMIN_CACHE` | 90 days |
| Daily health | Not cached | Today's values keep changing |

### Cloudflare plan

Parsing a FIT file takes tens of milliseconds of CPU (about 20–40ms for a 40-minute run), and long activities take more. The Workers Free plan allows 10ms per request, so uncached `get_activity` and `get_activity_streams` calls can fail there with error 1102. **Use Workers Paid** ($5/month), which allows up to 30 seconds. The other tools don't parse FIT files.

## Setup

You need Node 22+, a Cloudflare account, and a Garmin Personal API key from [Garmin Connect](https://connect.garmin.com/app/settings/personalApiToken).

This app lives in the `ortix/apps` monorepo. Install from the repo root, and run the commands below from `apps/garmin-mcp/`:

```bash
npm ci
```

### Local development

1. Create a GitHub OAuth app at <https://github.com/settings/developers> with:
   - Homepage URL: `http://localhost:8787`
   - Authorization callback URL: `http://localhost:8787/callback`
2. Create `.dev.vars` (gitignored) from the example, then fill in the GitHub values:

   ```bash
   cp .dev.vars.example .dev.vars
   ```

3. Add your Garmin key from your environment, so it never appears in output:

   ```bash
   printf 'GARMIN_API_KEY=%s\n' "$GARMIN_TOKEN" >> .dev.vars
   ```

4. Start the Worker, then run the Inspector check in a second terminal. It runs the full OAuth flow, calls every tool and prints only sizes and errors. Open the sign-in link it prints in a browser **on the same machine**, because both redirects go to `localhost`. Add `KEEP_AUTH=1` to reuse the login across runs.

   ```bash
   npm run dev
   ```

   ```bash
   scripts/inspector-oauth-check.sh
   ```

To check the Garmin client alone, `npm run smoke` prints field names and counts, never values.

### Tests

```bash
npm run typecheck
```

```bash
npm test
```

Tests run inside workerd with Garmin and GitHub mocked. The FIT fixture is synthetic, generated by `scripts/make-fixture.ts`, with no GPS or real data.

## Deploy

GitHub OAuth apps allow one callback URL, so production needs its own app.

The KV namespaces, Custom Domain and `MCP_SERVER_URL` are already set in `wrangler.jsonc`. For a fresh account, create the namespaces with `npx wrangler kv namespace create <NAME>` and replace the ids.

1. The Worker is served on the Custom Domain `garmin-mcp.tsutsu.dev`, set in `routes`. Cloudflare creates the DNS record and certificate on deploy. `workers.dev` and preview URLs are off. `MCP_SERVER_URL` must exactly match the URL you give claude.ai, because tokens are bound to it.
2. Create a second GitHub OAuth app with the callback `https://garmin-mcp.tsutsu.dev/callback`.
3. For the first deploy, upload secrets with the code, so the Worker is never live without them. Create `.env.production` (gitignored, `chmod 600`) containing `GITHUB_CLIENT_ID=…`, `GITHUB_CLIENT_SECRET=…` and the literal line `GARMIN_API_KEY=${GARMIN_TOKEN}`. Wrangler expands that line from your shell, so the key never sits in the file. Then deploy and delete the file:

   ```bash
   npx wrangler deploy --secrets-file .env.production
   ```

   ```bash
   rm -P .env.production
   ```

4. Later deploys go through the platform's CI and keep the existing secrets, because `wrangler deploy` never deletes or changes them. This app has `"autoDeploy": false` in `package.json`, so merging a change doesn't deploy it. Deploy it from the repo's **Actions** tab: **Deploy** › **Run workflow** › app `garmin-mcp`. The run typechecks, tests, deploys and checks that the OAuth metadata is live.

5. Watch production logs, filtered to paths, status codes and the Worker's own log lines:

   ```bash
   scripts/tail.sh
   ```

### Split DNS on the home network

`tsutsu.dev` is Tailscale split DNS, pointed at the UniFi gateway (`192.168.1.1`), which answers `*.tsutsu.dev` with a LAN address. The gateway has a **Forward Domain** policy sending `garmin-mcp.tsutsu.dev` to `1.1.1.1`, so browsers at home and on the tailnet reach Cloudflare for the sign-in. Without it, the GitHub login fails on those networks. claude.ai itself is unaffected either way.

## Add the connector on claude.ai

1. Go to [Customize > Connectors](https://claude.ai/customize/connectors) and click **Add custom connector**. On Team or Enterprise plans an owner adds it under Organization settings > Connectors.
2. Enter `https://garmin-mcp.tsutsu.dev/mcp` and click **Add**. Leave the OAuth client fields empty.
3. Click **Connect**, approve the consent page, and sign in with the allowlisted GitHub account.
4. In a chat, turn it on from the **+** button under **Connectors**. Connectors you add on the web are also available in Claude on desktop and mobile.

## Rotate the Garmin key

Garmin keys last 30, 90, 180 or 365 days, and Garmin emails you about a week before expiry. When a key has expired, tools return a message telling you to rotate it.

1. Create a new key at [Garmin Connect](https://connect.garmin.com/app/settings/personalApiToken). It's shown only once.
2. Update `GARMIN_TOKEN` in your shell profile and open a new terminal.
3. Replace the Worker secret, which takes effect immediately:

   ```bash
   printenv GARMIN_TOKEN | npx wrangler secret put GARMIN_API_KEY
   ```

4. Update `GARMIN_API_KEY` in `.dev.vars` if you develop locally.
5. Delete the old key on the Garmin page.

There's nothing to clear: the token cache is keyed by a hash of the API key, so a new key misses the old entry automatically. The connector on claude.ai keeps working.

## Security

- All tools are read-only and annotated as such. There is no authless endpoint or fallback.
- The GitHub login requests no scopes. Its token is used once to read your user id and is never stored.
- Logs go through `src/log.ts`, which only has fields for request id, tool name, outcome, status and timing. Cloudflare's invocation logs are off, because they would record full URLs, including OAuth codes. Error messages never include Garmin's response bodies.
- The connector's refresh token lasts 30 days from sign-in (the library default). Expect to click **Connect** again on claude.ai about once a month.
- To cut off access, change `ALLOWED_GITHUB_USER_ID`. Existing grants are refused on their next request.
- Secrets live in Wrangler secrets and the gitignored `.dev.vars`. Check for staged secrets before committing.
